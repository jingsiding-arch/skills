# Page Annotation Checklist

用于审查页面注解是否足够产品评审、研发开发、测试验收。

## 页面级注解

每个页面至少说明：

- 页面名称和业务定位。
- 使用角色和权限边界。
- 页面入口和返回路径。
- 关联业务对象和数据来源。
- 页面主任务和次任务。
- 与上下游页面的关系。

## 列表页

必须标注：

- 查询条件：字段、类型、默认值、枚举、是否支持多选、是否记忆。
- 列表字段：字段来源、展示格式、空值展示、排序规则。
- 行操作：显示条件、禁用条件、二次确认、操作结果。
- 批量操作：选择范围、跨页选择、权限校验、失败部分处理。
- 分页和导出：分页方式、导出范围、导出字段、权限。
- 状态：加载、空数据、查询无结果、接口失败、无权限。

## 表单页

必须标注：

- 字段类型、必填、默认值、占位提示。
- 枚举来源、联动关系、只读/禁用条件。
- 校验规则：格式、长度、范围、唯一性、跨字段校验。
- 提交条件、保存草稿、取消返回、重复提交防护。
- 提交成功、提交失败、部分失败、网络异常后的反馈。

## 详情页

必须标注：

- 基础信息、状态信息、关联记录、操作记录的分区。
- 状态展示和状态说明。
- 当前角色可见操作和不可见操作。
- 历史记录、审批记录、日志和附件。
- 数据刷新、变更提示、返回列表是否保持筛选条件。

## 审批/确认页

必须标注：

- 待处理对象、申请信息、影响范围、风险提示。
- 同意、驳回、退回、转交、撤销等动作的条件。
- 必填意见、附件、二次确认和结果通知。
- 审批后状态、下一处理人、历史记录。

## 弹窗/抽屉

必须标注：

- 触发入口、打开条件、关闭条件。
- 字段规则和按钮状态。
- 点击确认后的状态变化。
- 成功反馈、失败反馈、重复点击处理。
- 关闭后页面是否刷新、是否保留输入。

## 移动端补充

必须标注：

- 触控区域、底部按钮、吸底操作、长列表处理。
- 弱网、定位、拍照、扫码、蓝牙、人脸识别等系统能力失败处理。
- 键盘弹出、横竖屏、权限申请、后台切换。

## 常见缺口

- 只标了页面元素，没有标业务规则。
- 有新增/编辑，没有查看/撤销/删除/失败重试。
- 有状态字段，没有状态流转图。
- 有按钮，没有显示条件和禁用条件。
- 有审批动作，没有驳回后如何继续。
- 有导出按钮，没有导出范围和权限。
- 有通知要求，没有通知对象、渠道、触发时机和失败处理。
